# Gate 0.4.8 — доставка изображений

Выпуск объединяет media из #59 с актуальным main, включая безопасные повторы
и квитанции #61/#62. Серверная задача: Router #72, клиентская: EDT #207.
Фактическая установленная приёмка фиксируется в MEDIA72-DEPLOYMENT.md.

- Согласование `sdkTools.imageGeneration` проверяет политику организации,
  capability закреплённого узла и точный ACK Router.
- События `media_artifact` проходят через прежнюю привязку. Готовые каталог
  и байты доступны через `/harness/agent/sessions/{id}/media` и
  `/media/{artifactId}` с проверками владельца, организации, класса данных
  и разрешённого узла. ID/hash не заменяет авторизацию.
- Чтение сохранённого изображения не требует прежнего флага генерации,
  SDK login/quota или восстановления SDK после смены boot. Оно не запускает
  новую inference и не включает генерацию автоматически.
- Повторы mutation и чтение command receipts сохраняют контракт 0.4.7:
  unknown не разрешает новый prompt, ключ или смену маршрута. Для перехода
  старой беседы на новую capability создаётся отдельный запрос согласования
  с прежним SDK alias; исходный запрос создания не изменяется.
- Images/Responses API доступны по явно разрешённым gateway-маршрутам.
  Неизвестная стоимость изображения остаётся `null`, а не нулевой ценой.

Контракт и границы направлений: [IMAGE-GENERATION.md](IMAGE-GENERATION.md).
Повторы: [RETRY-RECEIPTS.md](RETRY-RECEIPTS.md).
Без обновления клиента серверный endpoint сам по себе не добавляет картинки
в интерфейс. Клиент должен сохранить событие/байты и проверить SHA256; старой
беседе нужен GET каталога независимо от прежнего ACK генератора.
