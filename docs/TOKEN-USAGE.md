# Учёт расхода токенов в Gate

Рекон и реализация: [#39](https://github.com/soltyy/atlas-gate/issues/39), Gate 0.3.0.

## Найденное поведение

Gate уже сохранял расход завершённых подписочных ходов с дедупликацией
по Gate session/turn ID. Вход считался как input_tokens + чтение кеша + запись кеша.
Но отдельный счётчик записи кеша, длительность и modelUsage терялись;
отсутствующие значения превращались в нули. В админке отчёта не было.

Router передаёт канонический usage: Claude — usage SDK, Codex — нормализованные
значения (input_tokens исключает cached input). Вход здесь означает суммарный
расход provider responses за ход, включая инструменты и субагентов.
Это НЕ размер контекстного окна. modelUsage Claude — дополнительная разбивка;
её нельзя прибавлять к уже агрегированному usage.

## Контракт

Админский GET `/harness/admin/usage` использует тот же X-Atlas-Token, что другие
защищённые маршруты админки. Токен устройства доступа к этому отчёту не даёт.
Параметры: since/until (Unix seconds, полуоткрытый интервал), org, device (ID),
model, route, kind, limit (1–200, по умолчанию 50), before (row ID).
Без периода — последние сутки. Параметры фильтров точные, SQL связывает значения.

Ответ: since, until, summary, groups, rows, nextBefore. Summary и groups относятся
ко всему фильтрованному периоду; before изменяет только страницу rows.
При пагинации нужно сохранять since/until и фильтры. UI это делает.
Все части ответа читаются в одной SQLite read transaction.

Метрики: totalInputTokens, uncachedInputTokens, cacheReadTokens,
cacheWriteTokens, outputTokens. Null означает отсутствие подтверждённого значения,
0 — измеренный ноль. Для totalInputTokens нужны все три составляющие входа.
Для каждой метрики summary/groups содержат `<metric>Records` — число записей,
где она известна. Суммы не подставляют неизвестные значения как нули.
cacheReadPercent рассчитывается как отношение сумм только по записям,
где известны totalInputTokens и cacheReadTokens; cacheComparableRecords — покрытие.
При нулевом знаменателе процент неизвестен.

Rows содержат Gate sessionId/turnId, deviceId, имя устройства и платформу,
route/model/kind, время записи ts, durationMs SDK, status success/failed/unknown,
source router-sdk/legacy и санитизированный modelUsage (только счётчики).
Время ts — момент учёта результата Gate, не начало обращения к провайдеру.
Длительность SDK не равна полной задержке клиент → сервер → клиент.
Промпты, ответы, токены авторизации, системные инструкции и файлы не сохраняются
в детализацию и не возвращаются отчётом.

## Хранение и восстановление

Новая таблица agent_usage_details добавляется к существующей БД автоматически.
Usage, receipt и детали фиксируются одной транзакцией. Повтор result и восстановление
не создают дубль. Версия схемы остаётся 2: добавление таблицы совместимо с откатом
на прежний Gate. Исходные historical usage не переписываются.

Исторические записи (и обычный gateway API без новых SDK-деталей) помечаются legacy.
Сохранённое положительное чтение кеша известно; исторический cached_tokens=0
не позволяет отличить отсутствующий счётчик от измеренного нуля и показан как null.
Историческую запись кеша и длительность восстановить из этих строк нельзя.

## Интерпретация

Низкая доля кеша — сигнал для исследования, не доказательство дефекта харнеса.
Причины требуют сопоставления одинакового префикса, повторного использования
сессии, модели и правил кеширования провайдера. Gate не хранит тексты для такого
сопоставления и не меняет SDK-запросы ради показателей. Короткий первый ход может
законно не читать кеш. Токены подписки не преобразуются в рубли/доллары.

Раздел «Расход» показывает устройства/модели, покрытие измерений и ходы,
подсвечивая подтверждённый нулевой cache read без оценки «неоптимально».
Обновление ручное: отчёт не добавляет фоновых запросов к SDK.

## Приёмка

Проверки: оба канонических формата SDK, missing/0/invalid, rollback одной транзакции,
повтор и открытие БД заново, исторические записи, фильтры/инъекция/пагинация,
защита HTTP API, Vue UI с авторизацией и сохранением периода.
Полный сетевой прогон использует отдельные базы, ключи и временные порты.
Живые проверки выпуска выполняются на Gate, без смены кода/настроек Router.
