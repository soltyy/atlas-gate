# Долгие команды сжатия (Gate #46)

`POST /harness/agent/sessions/{sid}/compact` с `Prefer: respond-async` и постоянным
`Idempotency-Key` принимает команду и возвращает HTTP202: `commandId`, `sessionId`,
`state: pending`. `Retry-After: 1` задаёт частоту проверки, а не предел длительности.
Результат читается через `GET /harness/agent/sessions/{sid}/commands/{commandId}`.
HTTP202 означает продолжающуюся проверку; терминальный ответ совпадает с результатом
Router и содержит `X-Atlas-Command-State: complete`. Чтение доступно только владельцу
устройства и организации, включая завершённую сессию. Ошибка/успех не выводятся из
одного истечения HTTP ожидания.

Без Prefer Gate сохраняет совместимость: возвращает окончательный ответ обычному
клиенту. На прямом соединении у compact нет общего 70-секундного read timeout.
Connect/write/pool остаются ограниченными техническими тайм-аутами. Обрыв ответа
не останавливает отслеживаемую команду. Через исходящий connector потерянный ответ
сверяется с журналом Router; промежуточный HTTP502 не становится ложным отказом SDK.

Команда закреплена за прежним Router и прежним ID. Gate restart восстанавливает
наблюдение по дисковому журналу, без повторной inference. Если Router перезапущен
и его собственный журнал сообщает unknown, Gate возвращает command_outcome_unknown:
автоматического нового запуска нет, нужна сверка результата. Сбой получения ACK
клиент проверяет повторным POST с тем же ключом и тем же payload.

DELETE незавершённой compact-сессии возвращает HTTP409 compact_pending. Очистка
после сетевой ошибки не должна отменять SDK. Явный Stop отправляет interrupt; после
подтверждённого завершения/отказа сессию можно закрыть. Локальную историю Harness
менять только после получения результата и записи канонической выжимки.

предварительную выжимку в17:49:14. Native compact не стартовал. Пользовательская
SDK-история сохранена; повторные пробы на ней не выполнялись.
