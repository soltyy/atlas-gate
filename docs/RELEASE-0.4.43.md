# Gate 0.4.43 — изоляция сетевых ожиданий

При медленном Router новые чаты ожидали общий замок Gate. Каждый ожидающий
probe повторно запускал проверку узла, что увеличивало очередь и задерживало
создание сессий, доставку и health. Исправлены совместный in-flight probe,
локальная отмена ожидателя и выбор кандидатов только нужного маршрута.
Сеть вынесена перед атомарным CREATE резервом. Внутри замка сохранены
повторные проверки владельца, ключа/тела, scope, SDK identity и лимитов.
Prompt/compact проверяют закреплённый узел.

Обычный CREATE больше не обходит старые чаты устройства; фоновая сверка
остаётся, а при достижении лимита выполняется дополнительная сверка вне замка.
Ошибочный probe не превращает старый snapshot в свежую identity.
Сессии, история, SDK bindings, вложения и квитанции не очищаются.
Результаты восстанавливаются с прежними ключами; инструменты не запускаются
повторно ради восстановления связи.

В canonical deploy исправлен порядок quiesce: после проверки отсутствия
SDK-работы закрывается новая admission, затем дожидается старый I/O.
Перед фактической остановкой по-прежнему обязательны пустые Router/Gate
и отсутствие detached API producers. Версия старого Gate читается через
аутентифицированный runtime, независимо от очереди SDK discovery в health.
Проверки rollback, ownership, контрактов, двух фаз ingress и резервная копия
сохранены. Обновление одного Gate не требует перезапуска Router.

Проверки и ограничения фиксируются в #144 / PR145. Пять новых сценариев
воспроизведены RED→GREEN, включая изоляцию Claude↔Codex и другой чат на том же
Router во время медленного resume. Installed admission_check: 20 races,
exact restart proof, sdkActions=0. Проверки canonical deploy на Linux:
35 passed. Полный набор Gate 0.4.43 не объявляется зелёным; ранее подтверждённый
baseline отказ cold files restore раскрыт отдельно в результатах HTTP прогона.
