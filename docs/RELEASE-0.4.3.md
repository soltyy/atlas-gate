# Gate 0.4.3 — восстановление доставки результата инструмента

Gate [#50](https://github.com/soltyy/atlas-gate/issues/50), клиентская задача
Harness [#303](https://github.com/soltyy/atlas_harness/issues/303).

После транспортного отказа tool_result Gate проверяет receipt той же команды
на исходном Router. Завершённый receipt возвращается без повторного POST.
При 404 повтор разрешён только с прежними node/boot, durable_commands,
тем же телом и тем же постоянным Idempotency-Key. Pending/неизвестный receipt,
смена boot, отсутствие boot в старой записи и недоступный Router дают временный
503 command_outcome_unknown, а не 409, который текущий Harness считает потерей хода.
Ожидание и число клиентских повторов остаются ограниченными.

Параллельные запросы одной доставки сериализуются в Gate; Router дополнительно
проверяет дисковый журнал команд. Инструмент, prompt и назначение другого узла
не повторяются. Проверки владельца, организации и fingerprint выполняются до
сверки/доставки. В безопасном журнале есть command/node/code и класс причины
транспортного отказа, без тела результата или токенов.

При старте добавляется nullable колонка router_operations.boot_id. Старые
неопределённые команды без boot не переотправляются автоматически; завершённый
receipt по-прежнему можно прочитать. Добавление колонки допускает откат к 0.4.2.

Сетевые регрессии используют настоящий HTTP Gate → два Router 0.8.2, временные
БД и сценарный SDK без подписки. Проверены сбой до приёма, потеря ACK после
приёма, конкурентные повторы, чужое устройство, изменение payload, pending,
недоступный/неверный receipt, смена boot и отсутствие durable-команд. На прежнем
agent.py сбой до приёма воспроизводится как 409; с исправлением ход завершается
с результатом инструмента без повторного исполнения.

Полный прогон исходников 15.10.2026: 124 passed, 6 opt-in skipped, 163.08 с.
Новые сетевые регрессии: 8 passed. Wheel и sdist 0.4.3 собраны через uv build;
uv.lock изменил только версию собственного пакета. UI/Router код не менялся.

Поставка Gate-only: отдельный каталог и SOURCE_REVISION, резервная копия SQLite
через backup API и конфигурации, проверка отсутствия активных ходов/compact,
атомарное переключение ссылки с health rollback. Router службы не перезапускать.
Истории/профили пользователей и unknown-операцию инцидента не переписывать.
Статус полного прогона, выпуска и серверной приёмки записывается в PR/тикет;
наличие этой заметки само по себе не означает развёртывание.
