# Gate 0.4.4 — воспроизведение отказа session-create

Исправление #52, совместный контракт с Router 0.8.3 (#65/#66).
Gate сохранял status=rejected после известного отрицательного ответа Router,
но повтор ключа отвечал command_outcome_unknown. Теперь терминальный HTTP
status и тело отказа записываются атомарно и воспроизводятся без нового создания.
Пустое и непрозрачное тело сохраняются побайтово; внешний JSON error code и
обёртка Gate остаются прежними.

При старте добавляются nullable router_bindings.rejection_status INTEGER и
rejection_body BLOB. Существующие строки и ready/unknown состояния не меняются;
откат к 0.4.3 допускает наличие дополнительных колонок. Старые rejected без
ответа сверяются с durable receipt Router только по явному повтору ключа,
а не бесконечным фоновым опросом. Complete/negative receipt восстанавливает
ответ. При неизвестном/expired/отсутствующем исходе создание не повторяется.

Ключ ограничен устройством и fingerprint запроса. Другой payload с тем же
ключом получает idempotency_conflict. Ready lost ACK возвращает прежний SID;
реальный unknown ждёт сверки с прежним узлом. HTTP-контракт не зависит от SDK,
production-код Gate не импортирует Router/вендорские библиотеки.

Обычный session-create клиента должен передавать устойчивый Idempotency-Key.
Если заголовка нет, Gate использует случайный ключ: два клиентских HTTP-запроса
не становятся одной операцией. Соответствующая задача Harness #304 остаётся
отдельной; ключи compact/documents её не заменяют. После известного отказа новая
логическая попытка использует новый ключ и прежний resume id, без повторного prompt.

Приёмка: реальные HTTP Gate → Router/journal с временными организациями/БД,
прежняя SDK/stub история с marker, known 502 и потерянный отрицательный ACK,
restart Gate, replay того же тела, конфликт и отдельный resume на том же node.
Проверены миграция старой схемы, legacy rejected с/без receipt и изоляция устройств.
Рабочее задание HH для этих проверок не запускается.

Полный прогон 16.10.2026: 137 passed, 6 opt-in skipped, 183.75 s.
Сетевые проверки используют Router из той же серии 0.8.3; существующий
набор доставки tool_result также включён. Зависимости uv.lock сохранены,
изменена только версия собственного пакета.

Поставка пакета не означает автоматический restart production. При развёртывании
сохранить backup SQLite через backup API и дождаться отсутствия активных ходов.
Не переписывать журналы/историю пользователя и не создавать повтор задания.

Оба собранных wheel установлены в отдельное окружение; 2 сетевых сценария
прошли при импорте production-кода из site-packages, без исходников пакетов.
