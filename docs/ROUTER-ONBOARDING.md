# Добавление Router через Gate

В админке откройте **Router → Добавить Router**. Gate регистрирует службу,
проверяет её готовность и предоставляет ей только выбранные организацию и маршруты.
Установку и вход в подписочный аккаунт выполняют на машине Router от пользователя
его службы. Gate не получает SDK credentials и не исполняет команды на чужой машине.

## Выбор соединения

| Где установлен Router | Выбор в мастере | Что требуется |
| --- | --- | --- |
| На машине Gate | На машине Gate | Свободный отдельный порт, loopback URL и ATLAS_TOKEN Router |
| Другая машина за NAT | На другой машине, за NAT или в закрытой сети | Исходящий HTTPS к Gate, одноразовое приглашение и одобрение отпечатка |
| Другая машина с доступным HTTPS | На другой машине с доступным HTTPS | Origin Router с доверенным TLS-сертификатом и ATLAS_TOKEN |

127.0.0.1 в прямом адресе означает машину **Gate**, а не компьютер с браузером.
Удалённый HTTP не допускается. Сертификаты проверяются, redirects запрещены.
Для корпоративной CA оператор может установить её в доверенное хранилище Gate
или использовать существующие ca_file/cert_file/key_file в nodes.json; мастер
не загружает приватные ключи. Исходящий канал поддерживает подписанный HTTPS
и отдельный mTLS listener при его включении в настройках Gate.

## Организация, маршруты и аккаунт

Выберите организацию и её действующие маршруты подписки. Мастер скрывает маршруты,
которые уже закреплены за другим поставщиком. Если подходящих маршрутов нет,
создайте их в разделе «Организации» и снова откройте мастер. Модели и агенты,
доступные устройствам, по-прежнему задаются в профиле организации.

Каждая служба Router использует одного поставщика и один SDK-профиль. На одной
машине могут работать несколько служб Claude/Codex с независимыми NODE_ID,
NODE_DB, портами и SDK home. Идентификатор постоянный: нельзя переименовать узел
и перенести на него существующие беседы простым изменением адреса.

**Другой аккаунт** создаёт новую группу ресурсов. **Тот же аккаунт** выбирает
существующую группу: Gate суммирует нагрузку и учитывает cooldown для всей группы.
Общий IP/провайдер/сеть не являются признаком общего аккаунта. Повторное имя группы
в режиме другого аккаунта отвергается; случайного объединения квот не происходит.

## Подготовка и завершение

Мастер показывает настройки .env и команды существующего CLI Router. Замените
пример ключа случайным секретом, NODE_DB — абсолютным путём службы. Установите
зависимости Router по его документации и войдите в Claude/ChatGPT на Router.
Наличие копии проекта ещё не означает установленную и запущенную службу.

Прямое соединение: введите адрес и ключ конкретного Router, нажмите
**Проверить и добавить**. До сохранения Gate проверит аутентификацию, NODE_ID,
поставщика, bootId, версию протокола и поддержку дискового журнала. При отказе
конфигурация не меняется, поля остаются для исправления. Router с подтверждённой
связью, но без готового SDK, требует локального входа; доступ к новым беседам
появится после ready=true и совместимого каталога моделей.

Исходящее соединение: **Добавить и получить приглашение**, затем:

1. На Router передайте приглашение через ATLAS_NODE_INVITATION и запустите
   показанную команду `uv run atlas-node enroll`. Приглашение живёт 15 минут.
2. В Gate нажмите **Проверить связь и заявки**. Сравните SHA-256 отпечаток с выводом
   команды на Router, одобрите заявку. Не одобряйте заявку по одному имени машины.
3. После успешного enroll запустите `uv run atlas-node run` с показанными адресами.
   Для mTLS требуются доступный отдельный порт и gate-ca.pem от администратора.
4. Зарегистрируйте connector как постоянную службу под пользователем Router.
   Проверьте связь: карточка должна показывать готовность, поставщика и нагрузку.

Gate не считает выдачу приглашения успешным подключением. Пока connector не
работает, карточка показывает ожидаемое действие. После закрытия мастера шаги
доступны через **Инструкция подключения**. Истёкшее приглашение можно выдать заново.
Повторная выдача сама не заменяет действующий ключ; новый ключ требует CSR approval.
**Отозвать** блокирует узел и его беседы до повторного одобрения.

## Ресурсы

По умолчанию три ограничения отсутствуют: ATLAS_NODE_CAPACITY=0,
ATLAS_NODE_TURN_CAPACITY=0, account_turn_capacity=0. **0 означает отсутствие
настроенного лимита**, а не отсутствие ресурсов. Исходный предел 4 снят по решению
пользователя. Положительное число — необязательная настройка оператора.
Ограничение бесед одного устройства ATLAS_GATE_AGENT_SESSIONS_PER_DEVICE также
по умолчанию 0; в новом развёрнутом контуре снимается прежнее значение 4.

Открытая SDK-сессия занимает слот и во время простоя. Сохранённая история на диске
сама по себе слота не занимает. Обычный ход резервирует одну единицу; ход с
объявленными субагентами — 1 + ATLAS_NODE_SUBAGENTS. Эта настройка дочерних
исполнителей отдельная и не является лимитом сессий или квоты подписки.

При нулевых лимитах Gate сравнивает абсолютную нагрузку, затем известное давление
квоты и число сессий. Для заданных лимитов сравнивает долю занятости. Cooldown,
readiness, совместимость моделей/маршрутов, drain, права клиента и постоянные
привязки бесед действуют независимо от значений лимитов. Ограничения тарифов
устанавливает поставщик; снятие операторского лимита их не отменяет.

## Контракт и сохранение

GET /harness/admin/node-options возвращает ревизию, действующие организации,
совместимые маршруты и группы аккаунтов. POST /harness/admin/nodes принимает
эту ревизию, node_id/backend/transport/org/routes/account_group/share_account,
account_turn_capacity, а для direct — url/token. Все запросы требуют admin token.
Списки и ошибки не содержат токены Router или приглашения.

Запись выполняется под замком Gate; устаревшая ревизия, дубликат ID и изменение
nodes.json внешним процессом отвергаются. Сначала атомарно сохраняется секрет в
закрытый файл, затем атомарно конфигурация. Сбой между этими действиями оставляет
неиспользуемый секрет, но не создаёт узел без credentials. На Windows права файла
определяет установленный ACL каталога данных; POSIX chmod не заменяет ACL.

Новый HTTP-клиент добавляется в действующий пул без замены существующих клиентов,
сессий и bindings. После рестарта nodes.json и node-secrets.env восстанавливают
узел. Внешнее изменение nodes.json требует контролируемого рестарта Gate.

## UX-решения и проверка

Выбран мастер реальной задачи с четырьмя именованными этапами, явным «Назад»,
сохранением ввода при ошибке и локальной помощью. Дополнительные ограничения
скрыты до запроса оператора. Основания:
[NN/g: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/),
[W3C WAI: Multi-page Forms](https://www.w3.org/WAI/tutorials/forms/multi-page/).
Текстовая правка карточек без регистрации оставляла бы ручной конфиг; автоматический
remote installer потребовал бы передачи SSH/SDK доступа Gate. Эти варианты не выбраны.

Приёмка включает настоящий HTTP для добавления direct/connector, неверные
token/NODE_ID/backend, CSR approval, сохранение/restart, конфликт ревизии,
разделение групп аккаунтов, UI-путь мастера и снятие предела на пятый слот/ход.
Ссылки на тикеты: Gate #21, Router #40. Тестовая среда использует отдельные данные
и свободные порты; старую рабочую службу Router не меняет.
