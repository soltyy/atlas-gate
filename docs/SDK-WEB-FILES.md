# Поиск SDK и оригиналы файлов — Gate contract v1

Связанные задачи: Gate #34, Router #58. Полный Router-контракт:
[SDK-WEB-FILES.md](https://github.com/soltyy/atlas-router/blob/main/docs/SDK-WEB-FILES.md).

Gate остаётся сетевым посредником и не импортирует SDK/декодеры. Исполнители:
Claude WebSearch/WebFetch или Codex web_search; общий SDK-инструмент atlas_file
исполняется изолированным worker Router. SDK выбирает способ разбора оригинала.

## Политика организации и профиль

Поиск и файлы доступны по умолчанию, галочки и предварительная настройка не нужны.
Необязательный override для административного ограничения:

```json
"sdk_tools": {"version":1, "webSearch":"live", "files":true}
```

Отсутствие поля означает live/true. cached разрешает только cached, live —
cached и live. Это разрешения на SDK-контур, не разрешение shell или файловых
инструментов клиента. Настройки подписанного профиля возвращают ту же политику.
У моделей `sdkTools` содержит доступные режимы и поддержку файлов. Источник —
Router node capabilities с учётом организации, маршрута и модели. Объединение
возможностей означает, что Gate найдёт совместимый узел, а не что любой узел
маршрута поддерживает функцию. Фактический ACK закреплённой сессии обязателен.

Не выводить право на поиск из названия подписки: SDK не публикует надёжную
матрицу entitlement всех аккаунтов. `accountAccess: unknown` честно сохраняется.
Окончательное подтверждение — успешный SDK-вызов; отказ поставщика не включает
другой аккаунт, API-ключ или платный fallback без отдельного маршрута.

## API для харнеса

1. Enrollment и проверка подписи `/harness/settings` — прежние.
2. `POST /harness/agent/sessions`: обычное создание без дополнительных настроек
   включает доступные SDK-инструменты выбранного узла. Ответ содержит фактический
   ACK `sdkTools`; явный объект в запросе позволяет требовать конкретные возможности. Старый ответ без ACK — отказ
   согласования, а не разрешение функции.
3. `GET /harness/agent/sessions/{sid}/sdk-tools`: `{sdkTools,catalog}` именно
   закреплённого узла. Не заменять его объединённым discovery.
4. `POST .../{sid}/files`: `{id,attachments:[{kind:"file",filename,mediaType,data}]}`,
   где data — base64 оригинала. Ответ `{files,requestId}` с SHA256 и размером.
   Стабильный Idempotency-Key сохраняется до подтверждённого ответа.
5. `GET .../{sid}/files`, `DELETE .../{sid}/files/{sha256}` — каталог и отзыв.
6. Обычный `/prompt`; SDK сам вызывает atlas_file. Base64 не надо снова
   вклеивать в сообщения/историю и не надо предварительно обрезать извлечённый текст.

Все операции проверяют device/org ownership. Gate использует сохранённую пару
node/local session, включая исходящий connector. Загрузка никогда не выбирает
«самый свободный» Router заново. Новый узел выбирается только при создании;
он обязан поддерживать запрошенные SDK-возможности. После reboot используются
штатные journal/reconcile и проверка прежней привязки.

События `sdk_tool_started`/`sdk_tool_completed` доставляются без преобразования
в `tool_call`. Харнес отображает ход и результат, но не исполняет инструмент и
не посылает tool_result. Клиентские tool_call продолжают работать как раньше.
Нативные источники и ошибки сохраняются; финальный текст не подменяет факт вызова.

## Поставка и приёмка

Сначала обновить Router/connector и проверить worker, затем Gate. Новые сессии получают доступные SDK-инструменты автоматически. Уже открытые
сессии сохраняют ранее согласованные параметры.
При откате прекратить создание новых SDK-сессий, дождаться/корректно завершить
активные ходы; не переносить их на старый Router, не понимающий контракт.

Проверки: `ATLAS_TEST_ROUTER_ROOT=<новый Router checkout>` с Python-окружением,
содержащим зависимости обоих проектов; `pytest`. `tests/test_sdk_tools.py`
проверяет policy, отказ missing ACK, выбор совместимого узла, direct/connector,
повтор загрузки, чужое устройство, отзыв разрешения и удаление оригинала.
Живое чтение случайного Excel-значения и нативный поиск проверяются отдельным
тестом Router на обеих подписках. Это не заменяет будущие UI-проверки харнесов.

Шаг 2: отдельные задачи EDT LLM, ЧатИИ и web Harness — состояние поиска,
передача оригиналов, ACK, восстановление и отображение SDK-событий. До исполнения
этих задач нельзя объявлять новый пользовательский сценарий готовым в их UI.
