# Источник ограничений входного текста

Gate #24, Router #50, EDT #176. Gate не задаёт собственные константы
maxFiles/maxRawBytes/maxTotalBytes/maxTextChars и не берёт минимум с ними.
Проверяются возможности узла, закреплённого за сессией. Если контракт неизвестен,
числовая проверка делегируется Router; формат base64/PDF продолжает проверяться.

`maxTextChars: null` — узел не вводит общего прикладного потолка текста.
В каталоге маршрута nullable агрегируется так: если хотя бы один кандидат имеет
реальный предел, публикуется минимум известных чисел; если все без потолка — null.
Это консервативное описание маршрута, не изменение контракта текущей сессии.

Окно модели и размер поля SDK — иные уровни. Router Codex делит большие text input
по границе поля RPC; Gate не вводит эту границу повторно для всего HTTP запроса.
Ошибки реального SDK не скрываются.

Совместимость: старые клиенты, требующие положительного maxTextChars, не принимают
nullable контракт. До обновления Router на production обновить харнесы. EDT получает
поддержку в выпуске по #176. Новый Gate совместим со старыми численными контрактами
Router. Не менять неизвестность на 0 или фиктивно большое число.
