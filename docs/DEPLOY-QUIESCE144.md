# Завершение drain при постоянном притоке запросов

После штатного Stop трёх Claude-ходов обе службы подтвердили SDK-счётчики0,
но до повторного запуска deploy был принят новый Codex prompt. Две попытки
правильно отказали до перезапуска. Требование свободных SDK до создания
admission fence не позволяло получить устойчивое окно при продолжающейся очереди.

Уточнён canonical guard: сначала проверяются готовность Router и отсутствие
чужого drain; затем применяется прежняя первая фаза запрета новой admission
и штатный node drain. Старые SDK-ходы, результаты инструментов и Stop продолжают
работать. После окончания старого I/O `wait_idle()` требует свободные SDK/Gate.
Вторая фаза и повторная проверка пустого состояния перед systemctl stop сохранены.
Автоматическая отмена или повтор инструментов не добавлены.

Linux-проверки canonical guard:46 passed, включая11 дополнительных вариантов
с активной исходной SDK-работой. Прерывание службы до подтверждения нулевых
счётчиков запрещено тестом. Отказ квалификации, rollback, потеря ACK drain/stop,
ownership маркеров, старые клиенты и живой поток с callbacks проверены.
