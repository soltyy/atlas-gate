# Где закрылось соединение CREATE

Наблюдатель работает отдельно от Gate, Router, HAProxy и SSH. На Gate он отмечает начало HTTP CREATE на входе от nginx, на управляющем входе селектора и на его выходе в прямой или резервный SSH. На машине Router он отмечает начало запроса на порту приложения. На этих же соединениях он отмечает заголовок ответа и пакеты FIN/RST с указанием направления. Для внешних SSH-соединений с настроенными узлами он фиксирует только FIN/RST.

Перед запуском проверьте роли, порты и адреса в `observe.py`. Нужны Linux, Python 3, iproute2 и tcpdump/libpcap. Поддерживаются IPv4 и Ethernet. Фильтр в ядре распознаёт начало HTTP/1 CREATE в одном сегменте. В процесс попадают максимум 54 байта Ethernet/IPv4/TCP. Программа сохраняет только время, тип события, адреса, порты, флаги и номера TCP. Первые пакеты приложения, текст, ключи и заголовки HTTP в файл не попадают. Журнал состоит из пяти файлов размером до 2 МиБ каждый, доступных владельцу службы.

Установите скрипт в `/usr/local/lib/atlas-session-observer/observe.py` и unit в `/etc/systemd/system/atlas-session-observer@.service`. Выполните `systemctl daemon-reload` и `systemctl enable --now atlas-session-observer@gate` на Gate, с экземпляром `@router` на машине Router. Это запускает отдельного наблюдателя. При выключении достаточно остановить собственный экземпляр. События находятся в `/var/lib/atlas-session-observer-<роль>/events.jsonl*`. Время `utc_us` — микросекунды Unix UTC с часов захвата пакета. Темп заполнения журнала зависит от нагрузки; запишите сегмент сразу после воспроизведения. Сверьте синхронизацию часов двух узлов.

При сбое сопоставьте вход Gate, исходящую попытку и вход приложения Router. Для каждого TCP-сегмента сравнивайте четырёхкомпонентную пару адресов и портов, направление первого FIN/RST и номер последовательности. HTTP traceId связывает Gate и Router после доставки заголовков в приложение. Если заголовки не дошли, используйте границы захвата и явно обозначьте неоднозначность при одновременных CREATE. Сокет SSH и внутренние проксируемые сокеты имеют разные номера последовательности. Флаг от локального SSH или HAProxy устанавливает точку закрытия на этом сегменте; его причину следует сверить на соседнем сегменте. Состояние SDK или принятие команды подтверждают приложение и журнал Router. Успешный выход из ASGI send сам по себе не подтверждает доставку клиенту.
